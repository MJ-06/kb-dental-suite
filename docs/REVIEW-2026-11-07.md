## Confirmed fixes and protections

- Daysheet stale responses reproduced with controlled out-of-order requests. Guard
  date changes/unmounts; failed reads do not become an empty day.
- Patient opening uses a latest-selection guard and progress feedback, so an older
  response cannot reopen a different patient or override later navigation.
- Care plans, treatment plans, clinical sheets and registration accept optimistic
  version checks. Return the version together with the data, not in a later read.
  The native client carries these versions into saves. Legacy clients without a
  version retain compatibility; they are not claimed to have conflict protection.
- Coalesce identical in-flight writes. Warn on leaving edited clinical screens or
  switching clinic, and while saves are pending. Do not clear edits made during a
  save. These protections are scoped to the main native workflows, not every old
  standalone/third-party client.
  These are in-memory guards, not durable server idempotency after a lost response.
  Shared organization demographic edits from different clinics and CRM collection
  replacement do not yet have the same conflict protection.
- Require POST for declared mutations and exclude mutations from read batches.
  Native requests carry values in bodies rather than query strings. Preserve legacy
  Apps Script transport where necessary; never retry ambiguous native writes.
- Validate clinical-message sender windows/origins and allowed flat-record actions.
  Do not trust a message merely because its type says save. No form values are sent
  by the dirty-state bridge.
- Dependency audit identified jsPDF/DOMPurify advisories. Upgrade jsPDF to the
  audited patched4.2.1 release and verify image/text/multipage export compatibility.
- Malformed JSON becomes a safe4xx response, rather than a spurious logged500.
- Static print previews are sandboxed without scripts or top-level navigation;
  printing remains allowed. This is separate from deferred PDF layout work.
- Issued CGHS bills retain their submitted address snapshot (migration0034).
  Existing bills remain unknown/blank rather than being silently backfilled from
  today's patient address.
- Strict TypeScript unused-symbol scan identified one unused document-handler
  argument; removed it. Excluded legacy `server/`, nested `kb-dental-suite/`, `nul`
  and unrelated untracked work are preserved, not guessed to be disposable code.

## Local analytics boundary

Umami runs separately on loopback8091, in its own marked database and restricted
role, with separate private login details. The clinical database role is not shared
with it. No new public analytics tunnel is created.

Only allowlisted screen names, registered action names, outcome and bounded duration
are emitted. Staff/clinic identifiers are HMAC pseudonyms. No patient identity,
UHID, phone, search text, free text, request body, credentials, real URL/query,
document content, screenshots, replay or keystrokes are collected. No browser SDK
or autocapture is installed. Emission is bounded and best effort; analytics failure
must not fail a clinical save. Product telemetry and geo downloads are disabled;
system fonts avoid an external font dependency in this local setup.

These are usage events, not the immutable clinical audit trail. They cannot prove
who used a shared admin login or reconstruct activity before tracking was enabled.
Use individual staff logins when attribution matters. Umami's database has separate
operations/backup requirements; it is not part of the clinical archive bundle.
