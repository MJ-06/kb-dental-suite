## New tab layout

- **Summary** keeps the existing report cards and common applied date range.
- **Doctor Details** adds searchable, paginated doctor totals and a drill-down of
  saved day-book entries and planned appointments. Recorded operating doctor and
  planned appointment doctor stay distinct. Combined doctor names stay together
  as recorded. No patient collections are attributed as doctor earnings.
- **Patient Details** adds searchable UHID/name totals and a drill-down of saved
  day-book, appointment and receipt rows. Identity/registration review flags and
  registration-date origins are visible. Missing UHIDs are counted as unlinked;
  names and phones are never used to infer joins. Receipts are collections in the
  range, not outstanding balances or total treatment fees.

Both lists and drill-downs paginate at 20 records. All tabs use the last successfully
applied range; editing date controls does not relabel stale data as a newly loaded
report. No patient data is edited or generated by these reports.

These are **working-clinic** reports, scoped by the authenticated session and
backend clinic context. Master → Organization → All-clinic Reports retains the
existing authorized-clinic summary; these new drill-downs do not silently combine
clinics or broaden access. Full doctor/item encounter history is still future work.

## API and storage

The UI reuses existing `/exec` reads: `getReceipts`, `getExpenses`,
`getDailyRegister`, `getAppointments`, `getAllPatients`, `getTreatmentsMaster`, and
optional `getFollowUps`. Main sources are receipts, expenses, daily_register,
appointments, patients/registration provenance and treatments. Calculations are
read-only in the browser; no report tables, schema migration or new API are added.
Existing API permissions and clinic isolation continue to apply.

## What Group means today

The legacy Other Clinic form stores `group` within `clinic_settings.clinic_profile`
→ `otherClinics` JSON. It is a text ownership label. It does **not** provision a
clinic, attach it to an organization, grant staff access or activate shared master
lists. The form now explicitly explains this, and calls it a legacy label.
Actual organization boundaries and working clinics come from organization identity,
operating-unit links and explicit staff clinic grants. The legacy copy/share choices
are saved profile metadata, not evidence that those provisioning operations ran.
